# 0.1.17 验证记录

日期：2026-11-07。起点：`c032c8c`（0.1.16 之后）。触发来源：issue #19 的后续回复（@nemovo911-ship-it，Windows 10、Antigravity CLI 1.5.2、agy-hud 0.1.16）：常驻的控制台窗口已经没有了，但偶尔还会极短地闪一下终端。

合入方式：分支 `feature/agy-auto-update-off` 线性 fast-forward 到 `main`。由维护者按 TDD 完成。

## 成因核实

reporter 用进程启动记录、`SetWinEventHook` 窗口事件和 agy 自己的日志对上了三次闪窗，链路都是：

```text
agy-hud quota refresh
└─ agy.exe -p /usage --output-format json --print-timeout 30s
   └─ agy.exe --bg-updater --app_data_dir=antigravity-cli --gemini_dir=.gemini
      └─ agy.exe --version        ← 闪窗时 Windows Terminal 前台的伪控制台客户端
```

agy 日志同时有 `auto_updater.go:334] Spawned background update process`。dsh-agy-link#49 在 1.4.2 上独立记录过同一条链。`--bg-updater` 是 agy 自己派生的，agy-hud 给 `/usage` 设的 `windowsHide` 管不到它的孙进程。

本机 agy 1.5.3 的实测：

- agy 每次启动都经过 `auto_updater.go`：第 247 行检查环境变量 `AGY_CLI_DISABLE_AUTO_UPDATE`，第 281 行是「上次检查不到 15 分钟」的 fast path，第 334 行派生 `--bg-updater`。
- 用 `agy -p /usage` 试了三个值：`true` 记 `Auto-update disabled via environment variable AGY_CLI_DISABLE_AUTO_UPDATE`；`1` 照样 `Spawned background update process`（当时上次检查已超过 15 分钟）；`0` 走 fast path。agy 只认 `true`。
- `agy plugin list` 不写 cli 日志，不走这条启动路径，doctor 里的那次调用不用改。

## 行为

- `queryUsage` 给 `/usage` 子进程的环境加 `AGY_CLI_DISABLE_AUTO_UPDATE=true`，覆盖环境里已有的值（包括 agy 不认的 `1`）。只作用于这一个子进程：用户自己的 agy 会话照常自动更新，`agy update` 不受影响。
- 没有采用 dsh-agy-link 0.4.66 的做法（每次 spawn 前刷新用户 profile 里 `last_check.timestamp` 的 mtime）：那会改动用户的 agy 状态，还连带推迟用户自己会话的更新检查；环境变量只影响这次运行，并且在 fast path 之前生效。
- 文档：AGENTS.md 增加这条规则及「只认 `true`」的实测；两份 README 的配额缓存一节说明子进程跳过更新检查；兼容性写到 1.5.3。
