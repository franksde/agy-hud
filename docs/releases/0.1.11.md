# 0.1.11 验证记录

日期：2026-09-25。起点：`a55cb74`（0.1.10 之后）。触发来源：适配 Antigravity CLI 1.1.27–1.2.11。

## 问题定性

- CLI 1.1.27 在状态栏 payload 中新增 `conversation_title`；1.1.28 起 `agy plugin install` 按源目录原样替换插件目录，放在插件目录里的 `config.json` 会在重装时被删除。
- CLI 1.2.2 起，`agy` 的本机 loopback 服务对 `GetUserStatus` 返回 `401 missing CSRF token`，而 CLI 不向插件提供该 token。本机缓存最后一次成功写入是 2026-09-15（1.2.3 发布当日）。版本边界 1.2.1 返回 200、1.2.2 返回 401，由 CodexBar 实测（steipete/CodexBar#3586、#3685），本项目在 1.2.11 上复现。
- 只剩 payload 里的官方配额时有明显滞后。1.2.11 实测：一轮回答进行中 payload 配额完全不动，而 `/usage` 显示 `gemini-5h` 在持续下降；一个空闲会话显示的 5 小时额度落后约 25 分钟。
- 合规取数途径只剩官方只读命令 `agy -p /usage --output-format json`：不启动 agent turn，token 为 0。实测一次约 7 秒，CPU 约 1 秒，峰值内存 160 MB，大部分时间在等 Google 接口。当前会话内拿不到配额：hook 只收到 `ANTIGRAVITY_CONVERSATION_ID`，stdin 里也没有配额字段（2026-09-25 实测）。

## 行为

- `show_title`（默认关闭）：显示会话标题。控制字符替换为空格，格式字符（bidi、零宽空格）删除，但保留 ZWNJ、ZWJ 和 tag 字符，保证组合 emoji、旗帜和波斯文断词正常；最多 24 列；宽度不够时最先省略。
- `doctor`：生效配置位于插件目录时给出提示，`--json` 新增 `configInPluginDir`、`userConfigPath`。
- 配额刷新：
  - 先试 loopback；被拒（401）时改走 `/usage`。
  - 拒绝按 CLI 版本记录在 `quota_cache.json.auth-rejected.json` 中，该版本之后直接走 `/usage`；CLI 升级后自动重新试 loopback。
  - loopback 的其他失败不回退，旧版 CLI 行为不变。
- `/usage` 只在后台运行，间隔如下：
  - 一轮进行中或刚结束：缓存超过 60 秒才跑。
  - 空闲：缓存超过 5 分钟才跑。
  - 失败退避从 60 秒开始翻倍，上限 10 分钟。
  - 全局一把锁，锁内写持有者 token：只有持锁者会跑 `/usage` 和释放锁；超过 120 秒的锁先改名移走再接管；手动刷新从不碰锁。
  - 子进程在私有临时目录中运行，45 秒后杀整个进程组，输出上限 1 MiB，不回显 CLI 错误文本。
- 防递归：`agy -p` 自己也会渲染状态栏，子进程带 `AGY_HUD_NESTED=1`，嵌套渲染只显示，不刷新也不写状态。
- 合并：5 小时和周窗口分别处理。已过期的读数让位；两份都未过期时视为同一窗口，取剩余更少的那份（剩余相同时取缓存，倒计时从当前时间算起）。未消耗桶的 `reset_time` 随查询时间浮动，所以不用它判断新旧。

## 独立审查轨迹

每轮两路，Codex 三个账号周额度仅剩 3–4%，低于派发门槛，记为 `codex skipped (quota)`，第二路改由 Claude Fable 子 agent 担任（与实现者不同模型）。

- r1：agy gemini-3.8-flash-high 与 Fable 并行。核实后修复锁的归属（接管后旧进程误删新锁）、无版本号 payload 下 `/usage` 无节流、按 `reset_time` 排序在浮动桶下不安全、缓存写入失败未退避、子进程占管道被误判超时、标题零宽字符。
- r2：同配置，只审 r1 修复。修复运行结束后仍发 SIGKILL、`\p{Cf}` 过滤误伤 ZWJ emoji、同值时倒计时陈旧。某版本首次被拒时 loopback 路径的锁不独占、可能并发两次 `/usage`，与 r1 同属一个根因家族，按规则上报，经 Frank 批准后改为「只有持锁者才能跑 `/usage`」（`c53ef9a`）。
- 收尾：agy 单路快检 `c53ef9a`，补上首次被拒时持锁子进程的完整路径测试，并改正跳过提示文案（`5533e81`）。
- 未修、记为已知限制：两个不同 CLI 版本的会话同时打开时，拒绝标记会互相覆盖（罕见，会自行恢复）；本机时钟偏差期间，刚结束的窗口可能多保留一段时间。

## 本地安装验证（Antigravity CLI 1.2.11）

- 按 README 暂存流程组装发布文件集，`agy plugin validate` 和 `agy plugin install` 均通过；已安装 bundle 与构建产物逐字节一致，`version` 报 0.1.11，`statusLine.command` 未变。
- 实测 1.1.28 重装行为：插件根目录与 `dist/` 下的 `config.json` 均被删除，`doctor` 提示正确。用户配置已迁到 `~/.config/agy-hud/config.json`，本次安装未受影响。
- `doctor --json`：`statuslineWired: true`、`configInPluginDir: false`。
- 手动 `quota refresh`：loopback 被拒后改走 `/usage`，7 秒写入缓存（`source: usage`，文件权限 600）。
- 后台链路：状态栏写入锁 token 并派出子进程，子进程确认持锁后运行（或因缓存新鲜而跳过）`/usage`，锁由持有者删除，无残留进程和临时目录。
- 用过期 payload 渲染：已结束窗口的读数让位于缓存，显示实时倒计时；嵌套渲染不写状态文件。
- 配额延迟实验、hook 字段实验、print 模式 loopback 实测（同样返回 401）的原始数据均未入库。
- 已观察到但未确定原因：一次拒绝标记在无 loopback 成功记录的情况下消失，随后由下一次刷新重新写回。影响仅为多一次 loopback 探测，可自愈。
