# 0.1.18 验证记录

日期：2026-11-21。起点：`624e718`（0.1.17 之后）。触发来源：维护者对照本机 Antigravity CLI 1.5.14、1.4.5–1.5.14 的 changelog 和官方 status line 文档做的兼容性排查，没有对应 issue。

合入方式：分支 `feature/cli-1.5.14-compat` 线性 fast-forward 到 `main`。实现由 agy（Gemini 4 Neon）按 TDD 完成，维护者审查后做了清理并发版。

## 核实依据

- 官方文档 `antigravity.google/docs/cli/statusline`：`statusLine.enabled: false` 停止运行自定义命令并显示内置状态栏，`command` 保留在 `settings.json`；`stack_with_default: true` 把自定义状态栏叠在内置状态栏下面；`agent_state` 的取值为 `idle`、`working`、`tool_use`、`reviewing`、`authenticating`、`initializing`、`error`；`plan_tier` 没有列出取值。
- agy 1.5.14 二进制内嵌的 changelog：1.4.7 起 print 模式不再启动自定义状态栏和窗口标题命令；默认 Agent Mode 改为 Auto（没有保存过模式的会话，包括 `-p`，在可用时以 Auto 启动）；1.5.10 起终端沙箱默认禁止命令读取 `~/.config`（或 `XDG_CONFIG_HOME`，Windows 上为 `AppData\Roaming`）。
- 实测的 1.5.14 payload：`model.display_name` 为 `Orchestrator (Carbon)`、`Orchestrator (Argon)`、`Orchestrator (Neon)`；本机 `plan_tier` 为 `Google AI Ultra`。

## 行为

- `doctor`：读取 `statusLine.enabled`。为 `false` 时 `statuslineWired` 为 `false`，新增字段 `statuslineEnabled: false`，`statuslineRunsInstalled` 为 `null`；被禁用的命令指向 agy-hud 时提示 `/statusline enable`，不再报 `not pointing at agy-hud`。
- `shortModelName`：`Orchestrator` 缩成 `Orch`。18 列上限不变（`Orchestrator (Carbon)` 原本是 19 列，被截成 `Orchestrator Ca...`）。
- agent state：`tool_use` → `Tool`，`working` / `reviewing` 与 `Thinking` 同为黄色，`initializing` 与 `Auth` 同为青色，`error` → `Error` 红色；未知状态的下划线换成空格。保留 `thinking`。
- 文档：两份 README、AGENTS.md、SECURITY.md 的验证版本更新到 1.5.14；`show_mode` 区分 `default` 模式和 Auto 默认启动；说明 `stack_with_default` 与 `/statusline off`；说明 1.4.7+ 的 `-p` 不再调用状态栏命令，`AGY_HUD_NESTED` 只对旧版 CLI 起作用，仍然保留；For AI Agents 一节加上沙箱读取 `~/.config` 的提醒，读取失败不能当作文件不存在。
- 测试数据：新增脱敏的 `testdata/statusline_payload_1.5.14.json`（`email`、会话 id 置空，路径只保留目录名）。

## 审查

- 维护者审查 agy 的两个提交：逐行核对 diff 和上面列出的文档依据，重跑 `npm test`，确认 `dist/` 没有漂移。
- 清理：删除 agy 额外加的 `"statusLine": false` 布尔写法的处理和测试。官方文档没有这种格式；删掉后它按未配置处理。
- 没有另外跑 codex / agy 的独立审查：实现方是 agy，审查方是维护者，范围限于上面这些小改动。

## 测试

- TDD：doctor、模型名、agent state 三项都是先看到测试失败，再实现（agy 记录的失败信息为 `'Orchestrator Ca...' !== 'Orch Carbon'` 等）。1.5.14 payload 的回归测试首次运行就通过，因为渲染能力已经存在。
- `npm test`：358 项全部通过，0 失败（本机 Node.js 24.22.1）。

## 本地安装验证（Antigravity CLI 1.5.14，macOS）

- 按 README 的暂存流程组装发布文件集：`agy plugin validate --strict` 0 error、0 warning；`agy plugin install` 通过。已安装目录与暂存的文件集 `diff -r` 一致，`status-line.sh` 保留可执行位。`version` 和 `agy plugin list --json` 都报 0.1.18、enabled。安装前后 `settings.json` 与 `~/.config/agy-hud/config.json` 的 sha256 不变。
- 已安装的 hook 渲染 1.5.14 payload 正常，退出码 0；带 `AGY_HUD_NESTED=1` 时没有输出。把模型换成 `Orchestrator (Carbon)`、状态换成 `tool_use` 后，显示为 `Orch Carbon` 和黄色的 `Tool`。
- `doctor --json`：`statuslineEnabled: true`、`statuslineWired: true`、`installedPluginStatus: found`、`statuslineRunsInstalled: true`。
- `quota refresh --cli-version 1.5.14` 走 `/usage`，26 秒完成，写入 4 个配额桶；`auth-rejected` 记录为 1.5.14，没有残留的 `agy-hud-usage-*` 目录。

## 未做

- 套餐识别没有加 Plus / Enterprise：没有这两种账号，拿不到 1.5.14 下 `plan_tier` 的真实字符串，这两种仍显示 `Plan ?`。
- Orchestrator 计入哪一组配额没有验证：目前读 Gemini 桶，`Orchestrator (Argon)` 在 payload 有 Argon 桶时读 Argon 的周额度。
- `GEMINI_API_KEY` 模式下 `/usage` 的退出码没有实测，退避逻辑不变（60 秒起，最多 10 分钟）。
- 官方 quota 桶的可选字段 `disabled`、`remaining_amount`，以及 payload 的其他新字段（`vim.mode`、`subagents`、`task_count` 等）没有处理。
- 没有在 Windows 和 Linux 上实际运行。
