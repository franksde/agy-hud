# 0.1.12 验证记录

日期：2026-10-03。起点：`e987bff`（0.1.11 之后）。触发来源：社区 PR #15（tazihad）。

## 问题定性

- Antigravity CLI 启动状态栏 hook 时不加载用户的 shell profile。只在 `.zshrc` / `.bashrc` 里初始化版本管理器的用户，hook 的 `PATH` 中没有 `node`，`hooks/status-line.sh` 以 `node: not found` 失败，HUD 不显示。
- PR #15 原实现只处理 nvm，并有两处问题：
  - `~/.nvm/alias/default` 的内容通常是 `22`、`lts/*` 这类别名，而不是 `v22.11.0` 这样的目录名，第一个分支多数情况下匹配不上，退到「最新安装版本」。
  - 用 `sort -V` 排版本，它不是 POSIX，而脚本声明的是 `sh`。

## 行为

- `node` 已在 `PATH` 上时只多一次 `command -v`，其余逻辑不执行。
- 找不到时依次查找：Volta、nvm、fnm、mise、asdf、nodenv、n（`N_PREFIX`、`~/n`、`~/.n`）、`~/.local/bin`、Homebrew（`bin` 与 keg-only 的 `opt/node@N`，认 `HOMEBREW_PREFIX`）、`/usr/bin`、`/snap/bin`。
- nvm 跟随 `default` alias：最多 8 跳的 alias 链（`lts/*` → `lts/jod` → `v22.11.0`），支持部分版本号（`22`）；alias 指向未安装的版本时取最高已安装版本。nodenv 读全局 `version` 文件，同样回退。版本文件首行的首尾空白、CR 和前导 `v` 都忽略。
- Volta 和 mise 不用 shim，直接取已安装的 `node`。shim 只有在管理器配置了版本时才能运行，不执行它就无法判断。代价是这两个管理器取的是最高已安装版本，而不是用户配置的默认版本。
- 版本号按数值比较。低于 Node 18 的安装跳过（bundle 跑不起来），超过三段或单段十位以上数字的目录名也跳过。
- 找到的目录追加到 `PATH` 末尾，不改变调用方 `PATH` 已能解析的命令。
- 都找不到时输出 `agy-hud: node not found on PATH or in a known version-manager directory`，退出码 127。
- 启动 node 之前只用 shell 内建命令；原先的 `dirname` 调用已去掉。
- `AGY_HUD_NO_SYSTEM_NODE` 是测试用开关，跳过固定的系统目录。没有它，「找不到」分支在装了系统 node 的机器（包括 CI）上测不到。
