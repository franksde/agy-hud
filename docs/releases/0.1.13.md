# 0.1.13 验证记录

日期：2026-10-15。起点：`4c2602b`（0.1.12 之后）。PR #16 以 rebase 合入。触发来源：Antigravity CLI 更新到 1.3.5 后核对 1.2.17–1.3.5 的 changelog 与真实 payload，过程见 `0.1.12.md` 的「1.3.5 复验」一节。

## 行为

- **agent 模式**：payload 的 `cycle_mode`（1.3.5）显示在模型段末尾、目录之前，`plan` 显示为 `Plan`（青色），`accept-edits` 为 `Accept Edits`（黄色），`auto` 为 `Auto`（橙色）。默认模式没有这个字段，那一行与以前完全一致。未知模式只在是普通标识符（字母开头，字母、数字、连字符，最多 24 个字符）时按连字符分词首字母大写显示，其余一律不显示。`show_mode` 默认开启。放进模型段的理由：模式和模型、套餐一样是会话设置，和每轮都在变的工作状态放在一起，容易读成一个状态。代价是在约 45 列以下的终端上，`Accept Edits` 会挤掉分支和工作状态。设计见 `docs/superpowers/specs/2026-10-15-cycle-mode-badge-design.md`。
- **doctor 检查已安装的插件**：在 CLI 1.3.4+ 上运行一次 `agy plugin list --json`（5 秒超时，丢弃 stderr），新增 `installed` 一行。状态栏接的是 agy-hud 但不在已安装目录下时，提示升级不会生效，并给出 `/statusline` 的重接命令。状态栏接的是别的工具时不做比对。比对前展开 `~/`、`$HOME/` 和 `${HOME}/`，不解析符号链接。列表读不到、不是 JSON 数组，或 agy-hud 条目没有路径时，结果都是 unknown。`doctor --json` 新增 `installedPlugin`、`installedPluginStatus`、`statuslineRunsInstalled`。设计见 `docs/superpowers/specs/2026-10-15-doctor-installed-plugin-design.md`。
- **嵌套 `/usage`**：`AGY_HUD_NESTED=1` 时，`hooks/status-line.sh` 用 shell 内建命令读完 stdin 后直接退出，不再查找和启动 Node；bundle 直接接入时同样只读完输入、不输出。在 1.3.5 上，一次后台刷新会调用 9 次状态栏。

## 1.4.5 复验（2026-10-22，发版后）

本机 CLI 自动更新到 1.4.5，用已安装的 0.1.13 复验。

Antigravity CLI 1.3.6–1.4.5 的官方 changelog（`agy changelog`）中与本插件相关的条目：

- 1.3.6、1.4.3：`/model` 新增 Claude Opus 5.5 / Sonnet 5.5（ADC 登录）与 Gemini 4 Argon。`shortModelName` 已去掉 `Claude` / `Gemini` 前缀，分别显示为 `Opus 5.5`、`4 Argon Med`。
- 1.4.0–1.4.4：`agy plugin validate` 逐版加严（未知字段、缺失的 hook 脚本、`--strict`、`--json`）。暂存发布文件集后 `--strict` 通过，没有 finding。
- 1.4.4：Windows 11 24H2 起支持 Auto mode，与 PR #17 的 Windows 支持相关。
- 1.4.5：画面无变化时暂停刷新。status line 只在重绘时运行，见下方空闲实测。

实测：

- 沿用 1.3.5 的做法，临时把 `statusLine.command` 换成先 tee 再 exec 原 hook 的包装脚本，在 tmux 中启动 agy（不发消息，不耗配额），抓到 27 份 payload，结束后 `settings.json` 按字节恢复（sha256 一致）。
- 字段与 1.3.5 相同，只多了配额桶 `gemini-argon-wtu-weekly`。官方 `/usage --output-format json` 把它单列为 `Gemini 4 Argon` 组，说明为「Pro 套餐的 Argon 配额单独计算；Ultra 套餐的 Argon 计入 Gemini 大组」，只有周额度，没有 5 小时额度。"Gemini Models" 组只包括 Flash 与 Pro。切到 Argon 后 0.1.13 显示的是 `gemini-5h` 100% 与 `gemini-weekly` 39%，而 Argon 自己的周额度已是 0。据此改为：Argon 有自己的配额桶时只显示这一个周窗口，否则沿用 Gemini 的配额桶。切到 Argon 时抓到的 payload 脱敏后存为 `testdata/statusline_payload_1.4.5.json`，抓完已切回 `Gemini 3.8 Flash (High)`。
- 进入空闲后 90 s 内状态栏一次都没有被调用。与「空闲期间没有刷新」的既有结论一致，后台刷新仍然只在 CLI 忙碌时触发。工作期间的调用频率没有测，因为要发消息、耗配额。
- loopback 仍然被拒，拒绝标记的 `cliVersion` 为 1.4.5；`/usage` 的 JSON 结构不变，`total_tokens` 为 0。`agy plugin list --json` 的条目结构不变。
- 未做：没有在 1.4.5 上重跑 `agy plugin install`（已安装的仍是 0.1.13 的发布归档）。
- 另见：窗口刚重置、CLI 还没重新拉取配额时，那一次重绘仍显示已结束窗口的读数与已过去的重置时刻（如 `87% (↻ 14:04)`）。1.3.5 上同样存在，持续不到一分钟，这次未处理。
