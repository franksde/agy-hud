# 0.1.16 验证记录

日期：2026-11-06。起点：`8e37b2e`（0.1.15 之后）。触发来源：issue #19（@nemovo911-ship-it，Windows 10、Antigravity CLI 1.5.2、agy-hud 0.1.15：额度刷新时间歇弹出两个控制台窗口，一个属于 `cmd.exe`，一个属于 FastCtx MCP server）。

合入方式：分支 `feature/windows-usage-no-detach` 线性 fast-forward 到 `main`。全部由维护者按 TDD 完成，审查修复同样先补失败测试。

## 成因核实

reporter 已经把问题缩到一个选项：从 Node 以 `windowsHide: true, detached: true, stdio: "ignore"` 启动 `agy -p /usage` 会弹两个窗口，只把 `detached` 改成 `false` 就不弹，退出码都是 0。他在已安装的 0.1.15 bundle 里改了这一处，手动 `quota refresh` 和重启 Agy 都不再弹窗。

机制（三路审查独立核对了 Node 18–24 各版本的 libuv 源码与 Win32 文档，结论一致）：

- libuv 在 Windows 上把 `detached` 实现为 `DETACHED_PROCESS | CREATE_NEW_PROCESS_GROUP`。
- `windowsHide` 在 stdio 没有任何 inherit 项时会加 `CREATE_NO_WINDOW`，但 Win32 规定它与 `DETACHED_PROCESS` 同用时被忽略。
- 于是 agy 没有控制台。它再启动的控制台程序（cmd.exe、MCP server）没有控制台可继承，各自新建一个可见窗口。
- 不 detach 时 agy 拿到一个没有窗口的控制台，它启动的程序默认继承这个控制台。

0.1.14 加 `windowsHide` 时以为「detached 子进程有自己的控制台，hide 能把它藏起来」，AGENTS.md 也写成了规则。这个理解是反的，本版一并更正。

## 行为

- **`/usage` 子进程在 Windows 上不再 detach**（`runAgy`）。macOS / Linux 照旧 detach，以便超时时按进程组杀掉 agy 启动的全部进程。平台可经 `RunAgyOptions.platform` 注入，测试不再改写 `process.platform`。测试锁定 `stdio: ["ignore", "pipe", "ignore"]`：任何一项改成 inherit，`CREATE_NO_WINDOW` 就会消失。
- **Windows 上超时或输出超限时结束整棵进程树**：以前只 `TerminateProcess` agy 本身，MCP server 会留下。现在同步运行 `%SystemRoot%\System32\taskkill.exe /T /F /PID <agy>`：
  - 同步运行，是因为 `spawnSync` 期间主事件循环处理不了 agy 的退出，libuv 不会关闭 agy 的进程句柄，而 Windows 不会复用仍有句柄打开的 PID，所以 taskkill 不会误杀一个拿到同一 PID 的无关进程（r2 的 P2）。阻塞只发生在后台刷新进程里。
  - Node 已经看到 agy 退出后不再运行 taskkill；一次 run 只运行一次。
  - taskkill 起不来、非零退出、超时（5 秒）或 `spawnSync` 同步抛错时，回退为直接杀 agy。
  - 按绝对路径调用；`SystemRoot` 为空或缺失时依次退回 `windir`、`C:\Windows`。
- **清理残留的 scratch 目录**：每次 `/usage` 前删除 `os.tmpdir()` 下一小时以前的 `agy-hud-usage-*` 目录。Windows 上被仍在运行的进程占用的 cwd 删不掉，以前会一直留着。
- **doctor 的 `agy plugin list`** 加 `windowsHide`，并在 `os.tmpdir()` 里运行：Windows 对裸程序名先查当前目录，doctor 又在用户工作区里运行，仓库里放一个 `agy.exe` 就会被执行。
- **文档**：AGENTS.md 的 Windows 规则改正；两份 README 的 Limitations 写明 taskkill 的行为与边界；CHANGELOG 写明 0.1.14 那句「不再弹窗」只对 agy 本身成立。
