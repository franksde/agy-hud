## 行为

- **Windows 支持（#17）**：新增 `hooks/status-line.cmd`。它只在 `PATH` 里查找 `node.exe`（`%%~$PATH:`），其他程序都写绝对路径。原因是 `cmd.exe` 遇到裸命令名时会先查当前目录，而状态栏就运行在用户的工作区里。嵌套的 `/usage` 运行中，它读完 stdin 后直接退出；找不到 node 时以 127 退出。不做版本管理器查找。`.gitattributes` 让它在各平台上都检出为 CRLF，release 归档会带上它。
- **Windows 上的配额刷新**：loopback 发现依赖 `ps` 和 `lsof`，Windows 上没有这两个工具。原先的结果是每次刷新都在 `ps` 处抛 ENOENT，永远走不到 `/usage` 回退。现在 `refreshQuota` 在 win32 上直接报告 loopback 被拒，沿用既有的拒绝标记、`/usage` 节流、退避和单一全局锁。两处 detached 子进程加上了 `windowsHide`。
- **Windows 上的 doctor**：
  - 比较路径时统一分隔符、忽略大小写，并展开 `%USERPROFILE%` 和 `~`；
  - home 缩写支持反斜杠和 UNC，盘符根和 share 根保持原样；
  - 重接命令用反斜杠；
  - 识别 Windows Terminal；
  - 关闭图标的修复命令改为 PowerShell，并带 `-Encoding ascii`；
  - 目录名写成 `AGY-HUD` 也算接上了 agy-hud。
- **BOM**：`config.json` 和 CLI 的 `settings.json` 以 UTF-8 BOM 开头时，也能正常读取。
- **Gemini 4 Argon**：Pro 套餐下，1.4.x 给 Argon 单独一个周额度桶 `gemini-argon-wtu-weekly`，没有 5 小时桶。HUD 改为只显示这一个窗口。有没有这个桶，在 payload 带 Gemini 配额时以 payload 为准，因为 Ultra 套餐的 payload 没有 Argon 桶。payload 不带 Gemini 配额时，交给 `/usage` 缓存判断。
- **文档**：
  - 两份 README 补齐了 Windows 的安装、`/statusline` 接线、关闭图标、给 agent 的那一节和归档内容清单；
  - 写明了 `/statusline` 命令不能带引号（tightship#89），路径含空格时用 8.3 短路径；
  - 写明了 Windows 上 CLI 版本的下限：antigravity-cli#344 于 2026-07-11 关闭，changelog 没有写明是哪个版本修的，此后的第一个版本是 1.1.2；
  - `SECURITY.md` 和 `AGENTS.md` 的 `## Windows` 一节同步更新。

## 独立审查轨迹

每轮三路并行：codex（`gpt-6.1-sol`）、agy（`gemini-3.8-flash-high`，Argon 的周额度已用完）、DeepSeek（`dsh-run`，effort max）。三路都用同一份提示词，提示词里写了基线句。

- r1（codex 用 xhigh 并联网调研开源项目；范围是 `main..2867bd9` 的 7 个 commit）：
  - DeepSeek P1：`.cmd` 用裸名调用 `node`、`where`、`more`，工作区里放一个 `node.bat` 就能被执行。已修。
  - codex P2：Ultra 的 payload 没有 Argon 桶时，缓存里残留的 Argon 桶会让 HUD 显示 0%。codex 在 `main` 和 HEAD 上用同一组输入对比复现了。已修。
  - codex 与 DeepSeek 的 P2 / P3：UNC home 被缩写成 `\\~\...`；打包测试只查文件名，不查目标目录；README 的图标方案和给 agent 的那一节仍是 POSIX 命令。已修。
  - DeepSeek P3：BOM、`AGY-HUD` 大小写、`doctor --json` 的 `platform` 字段、最低 CLI 版本。已修。
  - agy 的两条 P3（`for /f ... ('more')`、`%errorlevel%`）随 P1 一起改掉。
  - 不改：payload 无 version 时后台不走 `/usage`（既有行为，测试有意锁定）；旧式 loopback `models` 缓存在 Argon 周窗口下的整体替换（1.4.x 上不会产生这种缓存）；用引号包住的 `~` 路径（既有行为）。
- r2（codex 用 high；范围是 r1 的 4 个修复 commit）：
  - codex 与 DeepSeek 都报了同一个 P2：只要 payload 带了任意一个桶就由 payload 决定 Argon 的桶，于是只带 3p 桶的 payload 会让 Argon 的配额整行消失。这是 r1 修复引入的。已修：只有 payload 含 Gemini 系列的桶时，才由 payload 决定。
  - P3：防裸名的测试有漏洞，打包测试会把 `docs/hooks/` 也算作正确目标；文档里「从不运行当前目录的 node」说得过满，PATH 含 `.` 时仍会。已修。
  - agy 报的 P2：用 8.3 短路径接线时，doctor 会误判为另一份拷贝。doctor 按文本比较路径，不解析短路径，所以只写进 Limitations。
- r3（codex 用 high；范围是 r2 的 3 个修复 commit）：没有 P1 或 P2，已收敛。
  - codex 与 DeepSeek 的 P3：检查器会误报 `^&` 和引号里的 `&`；`%%~$PATH:` 的断言会被注释行满足（DeepSeek 用变异法证明：删掉那行 `for`，测试照样是绿的）；Argon 的说明文字和 r2 之后的行为不一致；Requirements 没有标出 Windows 的 CLI 下限。都已修。修复后用同样的变异法确认，测试会变红。
- 每轮跑完都核对过：agy 和 DeepSeek 的 worktree 没有被改动，主 worktree 仍在功能分支上。
- r1 的开源调研给出的、这批不做的建议：
  - doctor 用 `process.execPath` 直接打印接线命令（参考 claude-hud）；
  - 超时时用 `taskkill /T` 杀掉整棵进程树（参考 tree-kill 和 Gemini CLI）；
  - `readStdin` 加超时（antigravity-cli#698）。
